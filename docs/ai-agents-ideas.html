AI Agents for Bluejay CMS

Ten ideas for managing all your website content through AI — grounded in how your CMS actually works today. Current state: zero AI integration yet, but every content type (products, blog, solutions, case studies, whitepapers, partners, homepage, about, navigation…) already sits behind a clean, type-safe sqlc query layer and consistent CRUD handlers. That shared layer is exactly what makes AI agents practical to add.

First: How an agent "touches" your content

Before the ideas, there are three ways an AI agent can read & change content. Most ideas below reuse one of these. This is the single most important design decision.

Approach A — Tool-calling agent over your sqlc layer Recommended

The AI is given a set of "tools" that map directly to your existing database queries (ListProducts, CreateBlogPost, UpdateSolution…). When you ask it to do something, it calls those queries the same way a handler does. Safe, auditable via your existing activity_log, no HTTP/CSRF gymnastics.

Why it fits you: sqlc already generates a Querier interface — the agent's tools are thin wrappers around methods that already exist.

Approach B — Agent drives your existing admin HTTP endpoints

The AI calls the same POST /admin/products etc. routes the browser uses. Reuses all your validation, but you must handle auth/CSRF for programmatic calls. More moving parts.

Approach C — Inline field helpers (no agent loop)

Not a full agent — small "✨ Generate / Improve" buttons next to individual form fields. One prompt, one response, dropped into the textarea. Cheapest to ship, great as a first taste.

The Ideas

1

Conversational Content Manager (the "command bar")

Medium

A chat panel in the admin where you type plain English and it manages content end-to-end. The flagship "manage everything through AI" experience.

You say: "Create a blog post announcing our new partnership with Acme, tag it 'partnerships', and set it to draft."
It does: drafts the post, creates/links the tag, inserts a draft row, and shows you a preview link before publishing.

Maps to: blog_posts, blog_tags, every CRUD query via Approach A. Uses Claude tool-calling.

2

Content Generation Agent

Easy start

Drafts new content from a short brief: product descriptions, blog posts, case-study narratives, whitepaper abstracts, solution overviews. Matches your brand tone from a style prompt.

You say: "Write a product description for the BJ-500 sensor — emphasise ruggedness and IoT connectivity." → returns ready-to-edit copy for the product form.

Maps to: products, blog_posts, case_studies, whitepapers, solutions. Starts as Approach C, graduates to A.

3

Editor / Improver Agent

Easy

Takes existing content and rewrites for tone, grammar, clarity, length, or reading level. Works on the Trix rich-text blog body and any text field.

You say: "Make this case study 30% shorter and more executive-friendly."

Maps to: any text/HTML column — directly LLM-readable since content is stored as plain HTML/text in SQLite.

4

SEO Agent

Medium

Generates and maintains meta titles, meta descriptions, slugs, and keyword suggestions across all content. Can audit the whole site and flag pages with weak/missing metadata, then bulk-fix.

You say: "Find all products with no meta description and write one for each."

Maps to: all collections + your existing settings / SITE_BASE_URL / sitemap logic. Pairs well with your FTS5 search tables.

5

Content Audit & Gap Agent

Medium

Scans the whole CMS and reports problems: stale posts, products missing images/specs, broken or placeholder content, empty homepage sections, inconsistent terminology.

You say: "What's missing or low-quality on the site right now?" → a prioritised checklist you can one-click fix.

Maps to: reads across products+child tables, product_images, page_sections, etc. (Note: many seed /uploads/*.jpg are SVG placeholders — a natural thing to flag.)

6

Media / Image Agent

Medium

Auto-writes alt text and captions for images (accessibility + SEO), suggests which media to attach to which product/post, and flags missing or duplicate images.

Maps to: media_files, product_images, UploadService. Uses Claude vision for alt text.

7

Translation / Localization Agent

Larger

Translates content into other languages on demand. (Would need new locale columns/tables — a bigger lift, but the agent layer itself is the same.)

Maps to: all editorial collections; requires schema work first.

8

Bulk Operations Agent

Medium

Performs sweeping changes from one instruction across many records — safely, with a preview/diff and a confirm step before writing.

You say: "Re-categorise every product mentioning 'solar' into the Renewables category and add a one-line eco tagline to each."

Maps to: products, product_categories, batch sqlc updates wrapped in a transaction. Logs each change to activity_log.

9

Publishing Workflow Agent

Medium

Manages the lifecycle: draft → review → publish/schedule. Reviews drafts against a checklist (SEO done? image attached? tone on-brand?) and only then allows publish.

Maps to: status/published_at fields across collections, activity_log for the trail.

10

Site Q&A / Knowledge Agent

Medium

Ask questions about your content: "Which products don't appear in any solution?", "How many case studies mention energy savings?". A read-only analyst over your data — great trust-builder before you let agents write.

Maps to: read-only queries + your FTS5 search tables.

A suggested path

Phase 1 — Taste

Add the AI foundation (config for ANTHROPIC_API_KEY, a new internal/services/ai.go) + inline Generate / Improve buttons (Ideas 2 & 3) and the read-only Q&A agent (Idea 10). Low risk, immediately useful.

Phase 2 — Manage

Build the Conversational Content Manager (Idea 1) on Approach A, plus the SEO and Audit agents (Ideas 4 & 5). Now you're truly "managing content through AI."

Phase 3 — Scale

Add Bulk Ops, Publishing Workflow, and Media agents (Ideas 8, 9, 6) with preview/confirm guardrails and full activity_log auditing.

The one decision that unlocks everything

Pick Approach A (tool-calling over your sqlc layer) as the backbone. Almost every idea above becomes "just another tool" the agent can call. We build the engine once, then each agent is mostly a prompt + a set of allowed tools + a confirmation policy.
