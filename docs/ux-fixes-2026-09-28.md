## Additional code review findings


Source inspection found additional deployment/security concerns that this local UX change does not certify or remediate:

- `cmd/server/main.go` initializes sessions with a hardcoded signing secret, and `internal/middleware/session.go` sets the cookie Secure option to false. Move to a deployment-managed secret and environment-aware secure cookies in a dedicated hardening change with a planned session reset. No secrets or production configuration were changed in this review.
- CSRF middleware exists but is not mounted in the server setup. Review integration across normal forms and HTMX mutations; SameSite cookies are only one layer of protection.
- Public canonical/OG URL metadata contains a hardcoded historical host (`bluejaylabs.com`). This should be unified with deployment configuration in a separate SEO/configuration change.

These are source-assisted observations, not results from probing production or a complete security assessment.
